5 Experimental Configurations

Each configuration represents a different stage of the detection pipeline, evaluated independently using precision, recall, F1, AUC-ROC, and CAKR explanation quality scores.

1
Rules Only

Threshold-based rules: large transaction, velocity, structuring, and new-receiver checks. No ML, no LLM. Fully deterministic and interpretable.

2
ML Only

Random Forest + XGBoost ensemble with SHAP feature importance. Requires model training. No natural language explanations.

3
ML + LLM (Direct)

ML detection enriched with direct LLM-generated explanations. No retrieval context — LLM relies on its pre-training only.

4
ML + LLM + RAG

ML + RAG-augmented LLM explanations using a pgvector fraud pattern knowledge base. Grounded in domain-specific context.

5
Full System

Rules + ML + RAG + hallucination mitigation. The complete pipeline evaluated against all CAKR dimensions (Completeness, Actionability, Knowledge, Regulatory).

Quick Start

  1. Start infrastructure docker-compose up -d — starts PostgreSQL + pgvector + Ollama
  2. Pull LLM models (first time only) docker exec -it finguard-ollama ollama pull llama3.2 && docker exec -it finguard-ollama ollama pull nomic-embed-text
  3. Run the application ./mvnw spring-boot:run — app starts on localhost:8080
  4. Import data — upload a PaySim CSV or provide a server path
  5. Train ML models — required for ML-based configurations
  6. Seed knowledge base — loads fraud patterns for the RAG pipeline
  7. Run detection — choose a configuration and execute the pipeline
  8. Run evaluation — compare configurations with precision/recall/F1/CAKR metrics
