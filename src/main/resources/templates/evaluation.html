Understanding the Metrics
Precision
Of all transactions the system flagged as fraud, what fraction were actually fraud?
≥ 0.80 good — fewer false alarms.
Recall
Of all actual fraud, what fraction did the system catch?
≥ 0.80 good — fewer frauds slip through.
F1 Score
Harmonic mean of Precision & Recall.
≥ 0.80 excellent · 0.50–0.79 acceptable · < 0.50 poor
False Positive Rate
Fraction of legit transactions wrongly flagged. Lower is better.
≤ 0.10 good · > 0.30 alert fatigue
CAKR (1–5)
LLM-as-judge score on Completeness, Actionability, Knowledge, Regulatory.
≥ 4.0 excellent · < 2.5 poor
Hallucination Rate
Share of explanations with factual errors (wrong amounts, invented accounts, etc.).
≤ 10% safe · > 30% unreliable
Fold
Which slice of data was held out as the test set for that row (k-fold cross-validation).
0..k-1 = per-fold result · — (empty) = summary row (mean across folds)
Always quote the summary row in the thesis — it reflects stability across splits, not a single lucky slice.
Alerts
Number of anomalies the pipeline flagged on the test set for this config / fold.
Should be roughly proportional across configs that share a detection backbone (ML_ONLY, ML_LLM_DIRECT, ML_LLM_RAG all use the same ML step).
